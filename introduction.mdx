AI agents can already plan, reason, and call tools — but they stop cold at paywalls, token gates, and any task that requires moving real money. Nebula closes that gap. It is an MCP (Model Context Protocol) server that gives your agent a dedicated Stellar wallet, enforces spending limits you define, and handles all key management securely inside the Nebula Hub. Your agent never touches a private key; it simply expresses intent, and Nebula makes sure that intent stays within the bounds you set.

## How private keys work

Nebula uses a **Hub custody model**. When you sign in at [nebulaonchain.xyz](https://nebulaonchain.xyz), the Hub provisions a Privy embedded wallet on your behalf and assigns it a Stellar address. The private key for that address lives exclusively inside the Hub — encrypted and managed by Privy. It is never returned to you, never transmitted to your agent, and never written into any configuration file.

Your agent authenticates with a **bearer token** that looks like `nbl_live_…`. That token tells the Hub which wallet to use and which policy to apply. If the token is ever compromised, you can revoke it from the dashboard and issue a new one — the wallet and its funds remain safe.

<Note>
  Never put a Stellar secret key (`S…`) into your MCP configuration. Nebula is designed so that you never need one. If you are being asked for a secret key, something is wrong.
</Note>

## Who should use Nebula

Nebula is built for anyone who wants to give an AI agent safe, bounded access to on-chain capabilities:

- **AI agent builders** deploying autonomous or semi-autonomous agents that need to pay for APIs, services, or on-chain resources without manual intervention at every step.
- **Claude Desktop and Cursor users** who want to ask their AI assistant to send a payment, check a balance, or interact with Stellar — with guardrails that prevent runaway spending.
- **Developers building on x402 or MPP** who need a reliable USDC payment layer their agent can use without managing wallets themselves.
- **Teams running multiple agents** who want centralised policy control, a unified approvals inbox, and per-agent spending visibility from a single dashboard.
